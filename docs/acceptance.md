# 実環境受入試験計画書（Acceptance Test Plan）

本ドキュメントは、導入先の Google Workspace 実環境において、組織内デプロイされた GAS Artifact Hub が仕様通りに稼働するかを確認するための受入試験計画および検証チェックシートです。

> **重要**:
> ローカル自動テスト（Node.js / Playwright）は Google の本人識別、OAuth 認証、組織ポリシー、二重 iframe の挙動、実 Sheets/Drive の制約を代替しません。
> 本番公開・全社展開を行う前に、**必ず実際の Google Workspace 環境で複数アカウントを用いて以下の検証を実施してください**。
> **未実測の項目を「PASS」と記載しないでください。**

---

## 1. 受入試験の前提条件

### 必要な検証アカウント
- **アカウント A (管理者兼デプロイ担当)**: スプレッドシートおよび Apps Script の所有者。
- **アカウント B (一般社員 1)**: スプレッドシートや保存 Drive フォルダへの直接アクセス権を**持たない**通常ユーザー。
- **アカウント C (一般社員 2)**: スプレッドシートや保存 Drive フォルダへの直接アクセス権を**持たない**通常ユーザー。
- **外部アカウント D (A-4検証用)**: 個人 Gmail または別ドメインの実アカウント。A-4をPASSにするには実際のアクセス拒否を確認する必要があります。

### 1ライセンスで実施できる範囲

| 区分 | 対象 | 扱い |
| --- | --- | --- |
| 管理者Aだけで実施可能 | A-1、B-1〜3、D-1〜5、E-1〜4（13件） | 専用検証環境で実測し、証跡を記録 |
| 別の同一ドメイン実ユーザーが必要 | A-2〜3、C-1〜8（10件） | B/Cがいなければ保留。管理者の検証で置換しない |
| 外部実アカウントが必要 | A-4（1件） | 外部アカウントが利用できなければ保留 |

メールエイリアス、Googleグループ、同一アカウントの別ブラウザプロファイルは独立ユーザーではありません。DB/Driveへ直接アクセスできない一般社員としての本人識別・ACL失効の証明には使用しません。追加の実ユーザーを用意するか、協力組織の専用環境で残件を実測するまで本番受入は未完了です。契約変更・購入は管理者が別途判断します。

証跡には検証対象のソース版、デプロイ版、日時、アカウントの役割、ブラウザ、期待・実測・判定を記録してください。実メールや内部IDを含む証跡は非公開に保管します。別の組織での受入結果を、そのまま未検証の組織のPASSとして転記しません。

### 準備物
- `examples/hello-counter.html`（外部通信なしの標準アーティファクト）
- `examples/csv-analyzer.html`（ダウンロード機能を含むアーティファクト）
- 外部タグや通信を含むテスト用 HTML（警告・同意モーダル検証用）
- 1MB を超えるテスト用 HTML（容量制限エラー検証用）

## 3. 受入判定基準

1. **必須合格条件**:
   - 上記 A-1 〜 A-4、B-1 〜 B-3、C-1 〜 C-8、D-1 〜 D-5、E-1 〜 E-4 の24項目すべてがPASSであること。未実測・保留・FAILが1項目でも残る場合、本番受入は未完了とする。
   - 一般社員アカウント（DB権限なし）で権限分離が正常に機能していること。
   - `null` origin サンドボックスによる親フレーム防御が実機ブラウザで確認できていること。
2. **試験実施記録の保管**:
   - 実施した日時、実施者名、対象ブラウザ（Chrome, Edge, Safari等）、およびスクリーンショット等の証跡を記録・保管すること。

## 4. 追加の境界・運用検証

以下は24項目の置換ではありません。専用の検証環境で実施し、本番のデータを埋めたり障害を注入したりしないでください。
