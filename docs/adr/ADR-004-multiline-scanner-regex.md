# ADR-004: 改行・空白耐性を持つ静的検査スキャナーの採用

## ステータス
承認済み (Accepted)

## コンテキスト
投稿されたHTMLの透明性確認と同意判断を補助するため、`Scanner.gs` による静的解析を実施している。外部URL属性はタグ属性トークナイザで、他のルールは正規表現で検査する。
しかし初期実装では、単純な1行正規表現（例: `/<script\s+src=/i`）を用いていたため、以下の攻撃パターンですり抜け（Bypass）が発生することがサブエージェントレビューで判明した：
```html
<!-- 改行や多数の空白を挟むことで単純な正規表現をバイパスする例 -->
<script
  type="text/javascript"
  src="https://malicious-cdn.com/evil.js">
</script>
```

## 検討した選択肢
- **案A: 単純なキーワード検索（indexOf / includes）**
  - 単語の分割や改行に対応できず、誤検知（False Positive）と検知漏れ（False Negative）が多発する。
- **案B: GAS環境への本格的HTML/ASTパーサー導入**
  - CheerioやBabel等のASTパーサーをGASに持ち込むとバンドルサイズが肥大化し、実行時間制限（6分）を超過する恐れがある。
- **案C: 単方向タグ属性トークナイザと改行対応正規表現の併用（採用）**
  - 外部URL属性は引用符を考慮した単方向トークナイザで走査し、他のルールは改行・空白を許容する正規表現で検査する。

## 決定事項
**案C（単方向タグ属性トークナイザと正規表現の併用）を採用する。**
- 外部URL属性はHTMLを左から右へ一度だけ走査するタグ属性トークナイザで扱う。未閉鎖タグは入力末尾までを同じ区間として扱い、引用符内の疑似属性を除外する。
- 他のルールはHTML全文に対する正規表現で走査し、改行・空白を許容する箇所では `\s*` 等を使う。
- 5大カテゴリ（`NETWORK`, `EXTERNAL_TAG`, `POPUP`, `STORAGE`, `DYNAMIC_EVAL`）を定義する。行番号は検知位置から逆算して警告表示用に付与する。詳細は[セキュリティモデル仕様書 3.2節](../spec/02-security-model.md)を参照。

## 影響とトレードオフ
- **メリット**:
  - 追加ライブラリなしでGASサーバーサイドで実行可能。
  - 改行・空白・大文字小文字を挟んだ単純な回避パターンの検知漏れを減らせる（すべてのバイパス手法を防げるという保証ではなく、あくまで補助的な静的検査である）。
- **デメリット・留意点**:
  - タグ属性走査は未閉鎖タグや長大なタグ名を含む入力でも残り文字列を再走査しないようにする。他の正規表現ルールは、変更時に入力サイズと実行時間の回帰を確認する。
  - 静的解析である以上、動的に生成・難読化された文字列や本仕様がカバーしていない攻撃パターンは検知できない。最終的な安全境界はサンドボックス隔離（ADR-002）であり、スキャナーは透明性・同意促進のための補助である。
