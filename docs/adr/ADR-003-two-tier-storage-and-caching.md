# ADR-003: 90KB閾値による2階層ストレージとキャッシュ戦略の採用

## ステータス
承認済み (Accepted)

## コンテキスト
Google Apps Script (GAS) 環境でHTML実体を配信する際、以下の制約と課題が存在した：
1. **Google Drive API の呼び出し制限**:
   すべてのアクセスで `DriveApp.getFileById()` を実行すると、GASのクォータ（API実行回数・時間制限）を圧迫し、アクセス集中時にレスポンス遅延（1〜2秒以上）が発生する。
2. **`CacheService` の100KB容量上限**:
   GASの `CacheService.put()` は **1エントリあたり最大100KB** というハードリミットがあり、100KBを超える文字列を格納しようとすると例外エラーが発生して処理が停止する。

## 検討した選択肢
- **案A: 全ファイルをGoogle Driveから毎回読み込む**
  - 実装は単純だが、クォータ枯渇と表示速度低下のリスクが大きい。
- **案B: 分割キャッシュ（Chunking）を行う**
  - 100KBを超えるファイルを50KBずつ分割して `chunk_0`, `chunk_1` として保存・結合する。
  - 実装が複雑化し、キャッシュの整合性破損やパージ漏れのリスクが高まる。
- **案C: 90KB閾値による2階層ストレージ（採用）**
  - 実体HTMLが90KB以下のツールは `CacheService` に保存（TTL 10分 / 600秒）。
  - 90KBを超えるファイル（巨大ライブラリ等を内包）はGoogle DriveからUTF-8で直接ストリーム読み込み。

## 決定事項
**案C（90KB閾値による2階層ストレージ）を採用する。**
- 安全マージンを考慮し、100KB上限に対して **90KB** を分岐境界とする。

## 影響とトレードオフ
- **メリット**:
  - 軽量なツールは `CacheService` からDrive APIを呼ばずに返却できる（具体的な短縮時間は測定していない）。
  - 100KBを超える重厚なツール（Chart.jsや大きなデータ配列を含むHTML）もエラーにならず、Driveから安全に読み込める。
  - `CacheService.put()` の100KB上限エラーによるクラッシュを避けられる。
- **デメリット・留意点**:
  - 90KB超のツールは毎回Driveアクセスが発生するため、キャッシュヒット時より応答が遅くなる（具体的な遅延時間は測定していない）。
  - 90KB以下という割合が実際のツール群でどの程度を占めるかは未計測であり、この閾値は「Chart.js等を含む単一HTMLでも100KB上限に収まりやすい」という設計時の見積りに基づく。

## 改訂履歴

- **2026-09-05**: 当初案では公開バージョン解決用のメタデータ（`status`/`visibility`/`acl`/`current_version_id` 等）も `CacheService` に `meta_{artifactId}` キーでキャッシュする設計を検討していたが、緊急停止（`disabled`）やACL変更を次回アクセスへ即時反映させるため、現在の実装（[`src/Store.gs`](../../src/Store.gs) の `getArtifactForView()`）では認可に関わるメタデータをキャッシュせず、`withScriptLock_()` の内側で毎回Sheetsを正本として読み直す方式に変更した。キャッシュ対象はHTML実体（本ADRの90KB閾値によるキャッシュ）のみである。`Constants.CACHE.PREFIX_META` 定数は名残として残っているが、現在は未使用。詳細は[データ＆ストレージ仕様書 4.2節](../spec/03-data-and-storage.md)を参照。
