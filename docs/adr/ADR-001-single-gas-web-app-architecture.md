# ADR-001: 単一GAS Webアプリ＋単一スプレッドシート構成の採用

## ステータス
承認済み (Accepted)

## コンテキスト
社内メンバーが生成AIで作成した単一HTMLツールを共有・実行する基盤を構築するにあたり、以下の要件を満たす必要があった：
1. 外部ホスティングサービス（Vercel, Netlify, AWS, Cloudflare等）の契約・有料インフラ・サーバー管理コストを発生させないこと。
2. Google Workspaceの企業ドメイン認証をそのまま活かし、社外への情報漏洩を防ぐこと。
3. 導入企業において、専門のインフラエンジニアがいなくても数分で自己ホスト・展開できること。

## 検討した選択肢
- **案A: Cloudflare Workers + D1 / R2 構成**
  - 高速かつ安価だが、企業のGoogle Workspace OAuth連携やD1データベースの管理・クレジットカード登録が必要となり、非エンジニア部門でのセルフホストのハードルが高い。
- **案B: Google Cloud Run + Firestore 構成**
  - スケーラビリティは最高だが、GCPプロジェクトの作成、課金設定、コンテナビルド等の運用負担が発生する。
- **案C: 単一 Google Apps Script (GAS) Webアプリ + スプレッドシート + Google Drive 構成（採用）**
  - すべてGoogle Workspace標準機能（無料枠）で完結。スプレッドシートをコピーしてスクリプトをデプロイするだけで即座に稼働可能。

## 決定事項
**案C（単一GAS Webアプリ ＋ 単一スプレッドシート ＋ 専用Driveフォルダ）を採用する。**
- `executeAs: USER_DEPLOYING`, `access: DOMAIN` としてデプロイ。
- 管理者や利用者はGoogleアカウントでログインするだけで利用でき、外部サーバーも不要。

## 影響とトレードオフ
- **メリット**:
  - インフラコストが恒久的にゼロ。
  - Google Workspaceのセキュリティ境界内に全データが留まる。
  - `git clone` して `clasp push` するだけで誰でも社内環境にデプロイできる。
- **デメリット・制約**:
  - GASの実行時間制限（6分）や同時接続数制限がある（※静的配信＋キャッシュ戦略で影響を軽減しているが、負荷が高い場合の上限そのものを解消するものではない）。
  - リレーショナルDBほどの高速なクエリはできない（※シート設計とキー参照による探索で許容範囲に収めているが、大量データ・高頻度アクセス時の性能は未検証）。
