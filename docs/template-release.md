# 配布用テンプレート作成手順（Template Release Guide）

本ドキュメントは、自社の別ドメインや他組織へ GAS Artifact Hub を「スプレッドシートのコピー作成」方式で配布するための、**安全でクリーンなテンプレートスプレッドシートの作成・検証手順**を定めます。

初回OSSリリースにはコピー用Sheetテンプレートを含めます。手順書やソースの同梱だけではこの条件を満たしません。原本の作成、独立コピーでの初期化、共有設定の確認、実在するコピー導線の検証を終えてから配布します。一般公開前は原本を非公開に保ち、公開先・配布内容・共有設定について最終承認を受けます。

> **重要原則**:
> 1. **未公開・未作成のコピー用URLを絶対に捏造・掲載しないこと**。
> 2. テンプレート作成者の社内実データ、個人メールアドレス、Drive フォルダ ID、OAuth トークン、スクリプトプロパティ、トリガー、既存デプロイ等の機密情報を**一切持ち込まない（完全クレンジング）**こと。
> 3. コピー先環境で独立した保存フォルダを指定または自動生成でき、本人識別が正しく動作することを検証すること。

---

## 1. テンプレートに混入させてはならない情報（チェックリスト）

テンプレートを配布する前に、以下の項目が完全に空（または初期状態）であることを確認します：

| 分類 | 混入禁止項目 | リスクと理由 |
| --- | --- | --- |
| スプレッドシート | 実データ・テストデータ行 | 社内情報やテスト投稿のタイトル・URL・ファイル名が漏洩する |
| スプレッドシート | `system_config` 内の自社設定値 | 自社の `ALLOWED_DOMAIN` や自社 Drive の `STORAGE_FOLDER_ID` が残存するとコピー先で誤認・競合する |
| Apps Script | スクリプトプロパティ (`PropertiesService`) | テンプレート作成元の `SPREADSHEET_ID` が残存すると、コピー先が作成元のDBを参照しようとして誤動作する |
| Apps Script | トリガー設定 (Installable Triggers) | 作成元アカウントに紐づく実行トリガーが誤動作する |
| Apps Script | 既存デプロイ (Deployments) | 作成元のデプロイ設定やURLが引き継がれるリスク |
| Apps Script | 実行ログ・履歴 | 過去の実行ログに個人メールアドレスやIDが含まれる |

## 2. クリーンなテンプレートスプレッドシートの作成手順

### ステップ 1: 新規スプレッドシートの作成
1. Google ドライブで「新規」→「Google スプレッドシート」を作成します。
2. ファイル名を `[Template] GAS Artifact Hub` など、テンプレートであることが明確にわかる名前に設定します。
3. デフォルトで作成される `シート1` はそのままにし、**データやヘッダーを手動で入力しないでください**。

### ステップ 2: 本番ソースコードの配置（コンテナバインド）
1. スプレッドシートのメニューから **拡張機能 → Apps Script** を開きます。
2. プロジェクト名を `GAS Artifact Hub Template` に変更します。
3. デフォルトの `Code.gs` を削除します。
4. 本リポジトリの `src/` 配下にあるすべての本番ファイル（7個の `.gs`、6個の `.html`）を同名で新規作成・配置します。
5. 左側歯車アイコン（プロジェクトの設定）を開き、「`appsscript.json` マニフェスト ファイルをエディタで表示する」にチェックを入れます。
6. エディタに戻り、`appsscript.json` を `src/appsscript.json` の内容に書き換えます。

### ステップ 3: 【最重要】初期化スクリプトを実行しない
- **テンプレート原本では「GAS Artifact Hub → 初回セットアップ」を実行しないでください。** シートを開いてメニューが追加されるだけでは初期化されません。
- 初期化用の一時ファイル `RunSetupOnce.gs` / 関数 `runSetupOnce` は不要です。原本へ追加しないでください。
- 理由: 初期化を実行すると、作成者のドメイン、指定または生成された保存フォルダID、作成者のスプレッドシートIDが記録されてしまいます。
- 初期化は、**テンプレートをコピーした先の利用者が自身のアカウントで実行するもの**です。

### ステップ 4: プロジェクトのクレンジング確認
1. **プロジェクトの設定 → スクリプト プロパティ** を開き、プロパティが 0 件（空）であることを確認します。
2. 左メニューの **トリガー（時計アイコン）** を開き、トリガーが 1 件も登録されていないことを確認します。
3. 右上の **デプロイを管理**を開き、Web アプリまたは API 実行形式の公開デプロイを作成していないことを確認します。自動生成される開発用の `@HEAD` 表示は除きます。

## 3. 配布設定（組織内共有または一般公開テンプレート）

### 組織内での配布
- スプレッドシートの共有設定を開き、「リンクを知っている組織内の全員（閲覧者）」に設定します。
- 利用者には「ファイル → コピーを作成」を実行するよう案内します。

### URL によるコピー強制（推奨）
スプレッドシートの閲覧 URL の末尾 `/edit...` を `/copy` に変更したリンクを案内することで、利用者が開いた際に直接「コピーを作成しますか？」という画面を表示させることができます。
実在する原本のURLからコピー導線を作り、配布対象と同じ権限のブラウザで開いて確認します。未作成・未検証のURLを公式のコピーリンクとして記載しないでください。

## 4. コピー先での初期検証フロー（受入れ側での確認）

テンプレートからコピーを作成した利用者が、自身の環境で独立して正常にセットアップできるかを以下の手順で検証します。

1. **コピーの作成**:
   - 案内されたリンクからスプレッドシートのコピーを作成する。
2. **初期化の実行**:
   - コピーしたシートを開き直し、**GAS Artifact Hub → 初回セットアップ** を選ぶ。
   - [導入手順](setup.md#ステップ-3-シートのメニューから初期化)に従い、初回認証（OAuth同意）と保存先フォルダの入力を行う。一時関数やコードの編集は不要。
   - 空欄での新規フォルダ作成、指定IDでの保存先利用、キャンセルでの変更なしを専用の検証コピーで確認する。
3. **独立性の検証**:
   - スプレッドシートに 5 シート（`system_config`, `artifacts`, `versions`, `acl`, `audit_log`）が自動生成されたことを確認。
   - 空の `シート1` / `Sheet1` が削除され、管理シートの列数が順に3・11・9・5・6列へ整理されたことを確認。データがある初期シートや余剰列は保持されることも別の検証コピーで確認する。
   - `system_config` シートを開き、以下の 2 点を確認する：
     - `ALLOWED_DOMAIN`: コピーを実行したユーザーのドメインになっていること（テンプレート作成元のドメインではないこと）。
     - `STORAGE_FOLDER_ID`: 入力した専用フォルダのID、または空欄時にコピー利用者のマイドライブ直下へ新規作成された `GAS-Artifact-Hub-Storage` のIDであること（テンプレート作成元や他のコピーのフォルダではないこと）。
4. **Web アプリのデプロイ**:
   - 旧手順の `RunSetupOnce.gs` / `runSetupOnce` を残していないことを確認する。
   - 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選択。
   - 「次のユーザーとして実行：自分」「アクセスできるユーザー：組織内」を選択してデプロイ。
5. **動作確認**:
   - 発行された `/exec` URL を開き、ポータル画面が表示されることを確認。
   - 同一ドメイン内の別アカウントで開き、本人のメールアドレスが正しく識別されることを確認する。

### 配布前の独立性確認

検証用のコピーを2つ作成してそれぞれ初期化し、Spreadsheet ID・バインドScript ID・保存フォルダIDが互いに異なることを確認します。片方に検証用アーティファクトを投稿しても、もう片方と未初期化の原本にデータが増えないことを確認してください。元の空Sheetを社内稼働済みDBから複製して作る方法は採りません。

同じ管理者が作った2コピーで証明できるのは保存先の独立性です。一般社員の本人識別・DB直接権限分離、別会社ドメインでの導入を検証したことにはなりません。これらは[実環境受入](acceptance.md)に別記します。

一般公開の最終確認では、所有者、原本URL、閲覧者の範囲、コピーの許可、バインドスクリプトの閲覧範囲を提示します。Workspaceポリシーで公開・コピーできない場合は配布条件未達として扱い、架空URLや手順書だけで代用しません。
