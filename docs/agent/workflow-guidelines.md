# AIエージェント開発ワークフロー運用基準 (Workflow Guidelines)

## 1. 開発ライフサイクル (Agent Development Cycle)

AIエージェントが本リポジトリで作業を進める際は、以下の標準サイクルに従ってください：

```mermaid
graph TD
    A[ユーザー指示の受領] --> B[仕様書/ADR/コードの調査]
    B --> C[コード修正 / モック作成]
    C --> D[オフライン構文チェック & テスト実行]
    D -->|PASS| H{担当レビューの開始が許可済み?}
    H -->|はい| E[許可された独立レビュアーに差分を渡す]
    H -->|いいえ| I[実装検査済み・レビュー待ちを報告]
    D -->|FAIL| C
    E --> F{指摘事項はあるか?}
    F -->|あり| C
    F -->|なし (LGTM)| G[ユーザーへの完了報告 / 確認依頼]
```

## 2. サブエージェント（`agy`）レビュー運用手順

### 2.1 レビュー実行の必須条件
- ユーザー指示に「サブエージェントにレビューを貰いながら進めてください。レビューの指摘事項が無くなるまでユーザーに確認依頼しないでください」と定められている場合、**必ずこの手順を厳守** してください。
- ユーザーの担当指定・開始条件・再委譲禁止が常に優先します。レビュー必須を理由に未許可の担当を起動しないでください。開始できない場合は実装・検査結果とレビュー待ちを報告します。
- 担当内レビューは差分の品質確認です。ユーザーが別途依頼する正式最終レビュー、公開・本番反映の承認、実環境受入とは区別してください。

### 2.2 CLIコマンド実行例
```powershell
agy -p "【レビュー依頼内容の明確なプロンプト】"
```
- CLIは通常の権限確認を有効にして使用します。レビュー対象の差分と許可された操作を限定し、権限確認の省略を高速化の手段にしないでください。利用可能なネイティブの読み取り専用レビュー機能があれば、ユーザーが許可した範囲で使用できます。
- コマンド実行後にバックグラウンドタスク化する場合、完了通知を受信できる環境（MCPの完了通知・タスク通知の仕組みが使える場合）ではその通知を待って再開すること。通知の仕組みが無い、またはバックグラウンド実行自体に対応していない環境では、無意味な短間隔ポーリングをせず、結果を同期的に取得できる方法（コマンドの実行完了を直接待つ等）に切り替えること。

### 2.3 指摘への対応方針
1. 指摘されたコード箇所、理由、改善提案を精読する。
2. 再現と影響を確認し、担当範囲で必要な最小修正と回帰検査を行う。担当外の問題は所有担当へ返す。
3. 許可された開始条件の範囲で独立した再レビューを受け、指摘解消を確認する。未解消やレビュー待ちを完了と報告しない。

## 3. 新規UIコンポーネント追加時のチェックリスト

新画面やUIコンポーネントを追加・修正した際は、以下を自己チェックしてください：

- [ ] **絵文字排除**: UIアイコンに絵文字（⚡, 🚀, ✨ 等）を使っていないか？SVGになっているか？
- [ ] **配色**: ネオングローや派手なグラデーションを使っていないか？スレート＆コーポレートブルーになっているか？
- [ ] **ライト/ダーク両対応**: 背景や文字色のコントラスト比（WCAG AA: 4.5:1以上）を確保しているか？
- [ ] **アクセシビリティ**: 検索窓に `⌘K`、モーダルに `Escape`、ダイアログに `role="dialog"` `aria-modal="true"` が付与されているか？
- [ ] **Stored XSS対策**: ユーザー入力やHTMLソースコードを表示する際、`innerHTML` を使わず `textContent` を使用しているか？
- [ ] **UI被りなし**: ツール画面を覆い隠すフローティングバーを置いていないか？
